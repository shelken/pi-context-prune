# 共享 Viewer 的端口与数据目录错配

**日期**: 2026-10-11
**影响**: 不同宿主或 profile 复用 Viewer 时，页面与原文查询可能一直读取先启动进程的旧数据。
**发现人**: 主审（跨进程复验）

## 问题

Viewer 延续一个共享端口、最新发布者覆盖的设计，但 OMP 兼容改动将其数据目录跟随宿主 agent 目录。配置隔离是正确的，Viewer 数据隔离却与服务复用相冲突。

## 现象

```bash
bun test tests/viewer-shared-host.test.ts
```

测试启动两个真实进程，设置不同的 `PI_CODING_AGENT_DIR`，使用同一个临时 HOME 和端口。修复前，第二个进程报告 `alreadyRunning: true`，但 `/api/latest` 的 `servedSessionId` 和 `/api/original` 的文本仍来自第一个发布者。Pi→OMP 和 OMP→Pi 两个顺序均复现。

## 根因

错误假设是健康的服务可读取任何发布者的快照。实际服务的文件读取闭包绑定在启动进程的数据目录；健康和 UI 标记不能让它切换到另一个目录。单目录测试没有覆盖共享端口与不同目录的组合。

## 修复

- Viewer 页面、快照和原文 sidecar 统一使用 `~/.pi/agent/context-prune/`，不随宿主或 profile 改变；配置和会话索引仍然隔离。
- 存储作用域变化时同步更新服务及页面的 UI 标记，拒绝复用旧版本服务。
- 为测试预加载临时 Viewer 目录，避免普通扩展测试写入用户正在使用的共享快照。
- 双进程回归同时断言服务复用、最新会话、原文内容以及相同快照路径。

## 预防

- 修改端口、数据目录或 profile 支持时，执行上述双进程测试，覆盖两个启动顺序。
- 验证 `/api/latest` 和 `/api/original`，不能只验证健康检查或页面可打开。
- Viewer 测试使用临时 HOME/数据目录和随机端口，并在结束时关闭自建进程、删除临时目录。
- 更新存储布局时检查 `VIEWER_UI_MARKER` 与页面标记是否一致。
